# Project rules
- Keep onboarding geography and city ranking isolated in frontend modules with lazy local per-country assets; offline selections persist structured city details only on Continue and never add Google requests or coordinates.
- Use one orthographic projection for countries, regions, and graticule, clipped to a fixed circular globe viewport with an independent edge; scale zoom must not hide the circular frame.
- Keep Google city requests in the authenticated city-places function using the existing server key; resolve onboarding text once and reuse autocomplete tokens through Details, without requesting or persisting coordinates.
- Keep pre-account story cards and review progress in the shared onboarding story draft module, and migrate them on authenticated archive entry with stable row IDs; this preserves cards through confirmation and makes retries safe.
- Keep onboarding photo blobs in IndexedDB behind draft photo keys, and upload to deterministic user/memory paths during authenticated draft migration; retain blobs until all saves succeed to make retries safe.
- Reuse MemoryArtifact for onboarding review rather than duplicating its card contents; its opt-in photo-first frame leaves archive and capture presentation unchanged.
- Persist onboarding location as city, country_code and region_code only; never write latitude or longitude into the onboarding draft or the profile.
- Decide a signed-in user's destination from profile state in one shared helper: no stored city, no completion flag and no waiting draft sends them to the name screen, while a signed-in finish of the location screen writes the answers straight to the profile and opens the archive.
- Keep Sounds microphone capture in the shared AudioUpload control, returning browser-recorded audio as a File through the existing attachment flow and releasing microphone tracks on stop or unmount; this keeps capture and edit behavior consistent without new storage paths.
- Read and write people and touchstone_mentions only through the src/lib/people.ts data-access functions, never from components, so ownership checks (own person rows, mentions whose touchstone and person are both the user's) live in one place.
- Keep capture mentions in a shared picker and detached post-save helper, separate from touchstone and AI payloads, so optional people links cannot delay capture or leak names to AI.
- Render artifact mentions through one shared row and link to an owner-scoped person view using the people data layer, so detail views share chip behavior without component-level directory queries.
- Link person-page captures through an opt-in shared capture callback and people-layer ownership/category validation, so portrait creation reuses capture without changing ordinary saves or sending directory names to AI.
